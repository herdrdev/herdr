# Encargo para el agente: Shepherd, fase F11a — núcleo de snapshots locales por agente

Contexto en `SHEPHERD.md`: «Plan F11 — Snapshots locales por agente». Se implementa en local, sobre git, sin dependencias nuevas y sin enviar código a ningún servicio. Esta fase es **solo el núcleo + CLI + API tipada** (la integración con eventos es F11b; la UI es F11c). Sigue el estilo de herdr y de las fases F9: módulo propio en `crates/shepherd-core` (`snapshot/{mod,capture,restore,limits}.rs` o similar; archivos <~1000 líneas), método tipado `shepherd.snapshot.*` declarado como los demás (`src/api/schema/shepherd/snapshots.rs`, `Method`, `src/cli/shepherd_bindings.rs`, esquema JSON, golden y contrato como en F9b/F9c), CLI `shepherd snapshot …`. Reutiliza `crates/shepherd-core/src/git.rs` y lo que ya haya para git; usa la CLI de git (como el resto) en lugar de añadir una librería.

## Diseño (refínalo con evidencia y documéntalo)
- **Captura** de un worktree: crea un árbol con los objetos de git **sin tocar el índice ni la rama del usuario** (p. ej. `GIT_INDEX_FILE` temporal + `git add -A` sobre ese índice + `write-tree` + `commit-tree`), y guarda un ref oculto `refs/shepherd/snapshots/<agente>/<n>` (n incremental) con padre el snapshot anterior del mismo agente. Respeta `.gitignore`; descarta capturas cuyo árbol es idéntico al del último snapshot; excluye archivos mayores que un umbral configurable (default razonable) y binarios si se decide, anotando qué se omitió. Mensaje del commit = metadatos (agente, fecha, motivo `manual|idle|done|pre-restore|pre-clean|pre-kill`, resumen automático local: lista de archivos y conteo de líneas añadidas/quitadas respecto al snapshot anterior; **nada de IA ni red**).
- **Límites**: máximo de snapshots por agente (default p. ej. 50) y poda de los más viejos; tamaño máximo por captura; claves en `[shepherd.snapshots]` del `config.toml` de herdr (declárense también en `src/config/model.rs` y en `config-reference.json` como se hizo con `limits`, incluido el campo para que `config check` no avise de «unknown keys»; cuenta esas líneas de herdr en la métrica).
- **Uso**: `list` (por agente o por worktree, con id, fecha, motivo, archivos, +/-), `show`/`diff <a> [<b>]` (entre snapshots o contra el estado actual, resumen y diff completo bajo demanda), `restore <id> [--path <archivo>…]` (restaura archivos sueltos o todo el worktree; **siempre captura antes el estado actual como snapshot `pre-restore`**, no borra archivos no versionados sin decirlo y exige `--confirm` para restaurar el worktree completo), `delete <id>`, `prune [--agent X] [--keep N]`. Todo con `--json` y errores de uso/`{"error":…}` como el resto.
- **Seguridad**: nunca toca la rama, el índice, el stash ni los commits del usuario; si el repo no es git o el worktree está en mitad de merge/rebase, error claro; los refs viajan con el repo (`git gc` no los recoge porque están referenciados) y no se publican por `push` salvo que alguien los empuje a mano (documéntalo).

## Pruebas
Repos temporales (nunca el estado real ni `$HOME` real): captura crea ref y no altera índice/rama/`git status` del usuario; idempotencia (misma captura = sin snapshot nuevo); `.gitignore` y umbral de tamaño; poda; diff; restaurar un archivo y el worktree completo con `pre-restore`; restaurar con cambios sin commitear; repo sin commits iniciales; merge en curso; nombres con espacios y Unicode; límites de configuración (TOML y valores inválidos). Golden de las operaciones tipadas nuevas (solo archivos nuevos con `SHEPHERD_UPDATE_GOLDEN=1`) y de la salida humana de la CLI.
