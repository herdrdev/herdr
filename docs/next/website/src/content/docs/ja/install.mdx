---
title: Shepherd のインストール
description: Linux、macOS、Windows での Shepherd のインストール、アップデート、動作確認。
---

Shepherd は Linux、macOS、Windows 向けに安定版チャンネルのバイナリを提供しています。Windows 対応は正式提供されており、プラットフォーム固有の既知の制限と継続的な修正があります。

## インストール

Linux または macOS では次を実行します:

```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

Windows では次を実行します:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
```

エンドポイントセキュリティによってこのファイルレス PowerShell コマンドがブロックされる場合は、コマンドプロンプトを開いて次を実行します：

```cmd
curl.exe -fsSLo install.cmd https://herdr.dev/install.cmd && install.cmd && del install.cmd
```

インストーラーはプラットフォームに合ったリリースバイナリをダウンロードして PATH 上に配置します。新しい直接インストールは安定版アップデートチャンネルを使います。既存の Windows プレビューインストールは、`shepherd channel set stable` で切り替えるまでプレビューに残ります。Windows では PATH が有効なバージョン付きリリースディレクトリを指し、インストーラーは互換性のため `current` と安定した `bin` エイリアスも更新します。そのため、アップデート時に実行中の `shepherd.exe` を上書きする必要がありません。

## Homebrew でインストール

すでに Homebrew を使っている場合:

```bash
brew install shepherd
```

## mise でインストール

すでに mise を使っている場合:

```bash
mise use -g shepherd
```

mise が `herdr not found in mise tool registry` と報告する場合は、mise をアップデートして再試行してください。古い mise は Herdr のレジストリ登録より前のバージョンです。一時的な回避策として `mise use -g github:herdrdev/herdr` も使えます。

## Nix でインストール

すでに Nix を使っている場合、Shepherd はソースからビルドする flake を提供しています:

```bash
nix run github:herdrdev/herdr/v0.x.y
nix build github:herdrdev/herdr/v0.x.y
nix profile install github:herdrdev/herdr/v0.x.y
```

`v0.x.y` は最新のリリースタグに置き換えてください。タグを省略すると `master` を追跡できますが、通常のインストールにはリリースタグを推奨します。

flake は開発用シェルも公開しています:

```bash
nix develop github:herdrdev/herdr
```

アップデートは、Shepherd のインストールに使ったのと同じ Nix ワークフローで行います。プロファイルインストールの場合は、プロファイルのエントリを一覧して Shepherd のエントリをアップグレードします:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

Shepherd が自分の flake の input になっている場合は、その input を更新してシステム、Home Manager、または開発環境を再ビルドします:

```bash
nix flake update shepherd
```

## 手動でダウンロード

[GitHub releases](https://github.com/herdrdev/herdr/releases) からバイナリをダウンロードすることもできます。

システムに合ったアセットを選んでください:

| システム | アセット |
| --- | --- |
| Linux x86_64 | `shepherd-linux-x86_64` |
| Linux aarch64 | `shepherd-linux-aarch64` |
| macOS Intel | `shepherd-macos-x86_64` |
| macOS Apple silicon | `shepherd-macos-aarch64` |
| Windows x86_64 | `shepherd-windows-x86_64.zip` |

Linux または macOS では、実行可能にして PATH 上のどこかに移動します。

```bash
chmod +x shepherd-linux-x86_64
mv shepherd-linux-x86_64 ~/.local/bin/shepherd
```

### Windows アーカイブ

安定版リリースとプレビュープレリリースの両方に `shepherd-windows-x86_64.zip` が含まれます。アーカイブには `shepherd.exe` とアプリローカルの ConPTY ランタイムが含まれます。展開したディレクトリをまとめて保持し、`shepherd.exe` だけをコピーしないでください。

## 動作確認

Shepherd を起動します:

```bash
shepherd
```

シェルが `shepherd` を見つけられない場合は、ターミナルを再起動するか、インストール先ディレクトリが PATH に含まれているか確認してください。

## アップデート

Shepherd は新しいリリースをチェックし、アプリ内で通知します。手動でアップデートすることもできます:

```bash
shepherd update
```

`shepherd update` は Shepherd 自身のインストーラーで管理されているインストール向けです。Homebrew、mise、Nix のインストールは、それぞれのパッケージマネージャーでアップデートしてください。

Linux、macOS、Windows の直接インストールは、デフォルトで安定版アップデートチャンネルを使います。`master` からのプレビュービルドにオプトインするには、チャンネルを設定します:

```bash
shepherd channel set preview
```

直接インストールを安定版に戻すのも同じ方法です:

```bash
shepherd channel set stable
```

直接インストールの場合、チャンネルの変更はそのチャンネルをチェックして最新バイナリをインストールします。そのアップデートが失敗した場合は、`shepherd update` を実行して設定済みチャンネルから再試行してください。

プレビュービルドは、現在の開発ブランチから定期的に公開される GitHub プレリリースです。次の安定版リリースより前に修正が欲しいときに便利ですが、リグレッションの可能性があります。Homebrew、mise、Nix のインストールはプレビューチャンネルを使いません。

プレビューチャンネルでも、安定版のバージョンが最新プレビューのベースバージョンより高ければ、その安定版をインストールします。設定はプレビューのままなので、その安定版をベースにした後続のプレビューも自動的に更新候補になります。インストール済みのバイナリより古いバージョンをベースにしたリリースは、更新候補として表示されません。

Windows の通常利用には安定版を推奨します。プレビューでは修正をより早く受け取れますが、リグレッションの可能性があるため、そのトレードオフを望む場合に限りオプトインしてください。既存の Windows プレビューインストールは、明示的に切り替えるまでプレビューに残ります。古いプレビュービルドで `shepherd channel set stable` が拒否される場合は、プレビューのまま一度 `shepherd update` を実行してから、チャンネル切り替えを再試行してください。

デフォルトでは、`shepherd update` は新しいバイナリをインストールし、エンドポイント世代 1 のサーバーとペインプロセスを動かしたままにします。再度 Shepherd を起動すると、更新済みクライアントで再接続します。クライアントだけの変更はすぐに使えます。新しいサーバー側アクションは、そのサーバーを更新して再起動するまで利用できず、クライアントは切断せずに通知を表示します。エンドポイント世代 1 より前のサーバーだけは、更新時に最後の 1 回の停止が必要です。

完了時に `shepherd update` は、古いバージョンのまま動いているサーバーとそれを再起動するコマンド、そして独自の Shepherd を動かしている保存済み SSH マシンを一覧表示します。各マシンでも `shepherd update` を実行して更新してください。

対応する実行中セッションで実験的なライブサーバーハンドオフにオプトインするには:

```bash
shepherd update --handoff
```

両方のサーバーがエージェント状態の転送に対応している場合、ライブハンドオフはフックが報告したエージェント状態を次の報告が届くまで維持します。古いサーバーからハンドオフすると、実行中のエージェントが一時的に idle と表示される場合があります。

ライブハンドオフは Homebrew、mise、Nix のパッケージマネージャー経由のアップデートには適用されません。それらのインストールではパッケージマネージャーで更新し、再度 Shepherd を実行して更新済みクライアントで再接続します。互換性のある古いサーバーは動き続けます。新しいリリースのサーバー側変更が必要になったときだけ、`shepherd server stop` または `shepherd session stop <name>` で後から再起動してください。

## 動作要件

安定版チャンネルのバイナリは Linux、macOS、Windows x86_64 で利用できます。サポートされるワークフローと既知の制限は [Windows サポート](/ja/docs/windows-beta/)を参照してください。Windows ARM64 では x86_64 ビルドが Windows のエミュレーション上で動作します。
