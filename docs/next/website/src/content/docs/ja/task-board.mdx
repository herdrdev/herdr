---
title: タスクボード
description: 永続的な作業を自動化し、エージェントへ配布して、ライフサイクルのアクティビティを追跡します。
---

Herdr のタスクボードは、人間とエージェントの作業を管理する、サーバー所有のコントロールプレーンです。タスクはセッションと一緒に保存されるため、クライアントの切断後やサーバーの再起動後も利用できます。タスクはペインから独立しており、後から実行中のエージェントに割り当てられます。ペインを別のワークスペースへ移動してもタスクは失われません。

## ワークフローが自動化するもの

Symphony スタイルのワークフローでは、永続的な作業キューを、作業の定義、ready 項目の選択、ワーカーへの配布、進捗の観察、結果のレビュー、依存作業の解放という制御ループにします。これは [OpenAI の長時間実行ゴールのガイダンス](https://learn.chatgpt.com/use-cases/follow-goals) にある永続的な目標のパターンと一致します。目標と停止条件を明示し、関連するコンテキストと境界、検証エビデンス、短いチェックポイント更新を定義します。

| ワークフローの概念 | Herdr のプリミティブ |
| --- | --- |
| 永続的な目標 | タイトル、説明、作業ディレクトリ、優先度、依存関係を持つタスク |
| 作業キュー | サーバー所有のタスクリストとステータスボード |
| コーディネーター | タスク CLI または Socket API を使う人間、エージェント、スクリプト |
| ワーカー | Herdr ペイン内の名前付き実行中エージェント |
| 分離された実行環境 | ワークスペース、worktree、タブ、ペイン |
| 配布 | `herdr task dispatch` |
| 進捗と可観測性 | ステータス報告、アクティビティ履歴、エージェント検出、TUI |
| 受け入れゲート | `review` の後の `done` |

Herdr は、このループに必要な永続キュー、配布、状態機械、アクティビティ履歴、オペレーター UI を提供します。どの ready タスクをどのワーカーで実行するかは、人間またはコーディネーターエージェントが決めます。Herdr には、エージェントを作成してコーディネーターなしでキューを消化する組み込みバックグラウンドスケジューラーはまだありません。

## 人間オペレーターのワークフロー

1. 検証可能な成果を 1 つ定義します。説明には受け入れ基準、制約、検証コマンドを含めます。`--cwd` で対象プロジェクトにタスクを結び付けます。
2. 無関係な成果や個別にレビューできる成果は別タスクに分割します。先行タスクが受け入れられるまで開始できない場合は `--depends-on` を使います。
3. 必要なエージェントを Herdr ペインで起動し、`implementer` や `reviewer` のような安定した名前を付けます。
4. ready タスクを配布します。Herdr は選択したエージェントにタスクを割り当て、`running` に変更し、タスクのコンテキストを次のプロンプトとして送信します。
5. タスクパネルまたはアクティビティモーダルを監視します。タスクが `blocked` になった場合、承認が必要な場合、進捗報告から方針のずれが分かった場合に介入します。
6. ワーカーが `review` を報告したらエビデンスを確認します。受け入れ基準を満たした後だけ `done` にします。依存タスクは自動的に `ready` になります。

例:

```bash
created=$(herdr task create \
  --title "Add retry policy" \
  --description "Add bounded retries. Run just test and update the operator docs." \
  --cwd ~/src/project)
task_id=$(printf '%s\n' "$created" | jq -r '.result.task.id')

herdr task dispatch "$task_id" implementer
herdr task get "$task_id"
herdr task report "$task_id" done --message "Review accepted; just test passes"
```

最後のコマンドは、タスクが `review` に到達した後だけ有効です。

## ワーカーエージェントの契約

`task dispatch` は、タスク ID、タイトル、説明、進捗報告の指示をワーカーへ渡します。カスタム配布プロンプト、エージェントポリシー、`AGENTS.md` では、次の契約を使えます。

```text
あなたは Herdr タスク TASK_ID を担当しています。

1. ファイルを変更する前に `herdr task get TASK_ID` を実行します。
2. 明示された成果だけに取り組み、制約と依存関係を守ります。
3. 意味のあるマイルストーンで、次のコマンドを使って短い可視の要約を報告します。
   `herdr task report TASK_ID running --message "<完了した作業と次のステップ>"`
4. 続行できない場合は、再開に必要な外部判断、権限、入力、失敗を正確に示して `blocked` を報告します。重大なブロッカーを黙って回避し続けません。
5. タスクの検証を実行します。実装とエビデンスが受け入れ可能になったら、短い結果要約とともに `review` を報告します。
6. 非公開の思考過程を報告しません。成果、エビデンス、判断、ブロッカー、次のステップだけを記録します。
```

進捗メッセージはオペレーター向けのチェックポイントであり、トランスクリプトではありません。意味のある状態変化の後、長い待機の前、計画変更時に報告します。すべてのコマンドやツール呼び出しを報告しないでください。

実装ワーカーは通常 `review` で停止します。受け入れ判断と `done` への移行は、レビュアー、人間、コーディネーターが担当します。

## コーディネーターのワークフロー

コーディネーターには、別のエージェント、シェルスクリプト、Herdr の Socket API を使うサービスを利用できます。次の限定された手順を繰り返します。

1. `ready`、`blocked`、`review` のタスクを一覧します。
2. 優先度、依存関係、プロジェクト所有者、利用可能なワーカーに基づいて ready タスクを選びます。優先度は数値が小さいほど先に並びます。
3. 1 つの名前付き実行中エージェントへタスクを配布します。
4. アイドル端末から完了を推測せず、タスクのステータスとアクティビティを観察します。
5. blocked タスクを人間へ、review タスクを受け入れ担当者へ送ります。
6. 再試行が妥当な理由を記録した後だけ failed タスクを再試行します。

タスクリストと取得レスポンスは JSON なので、自動コーディネーターは TUI をスクレイピングせずに利用できます。

```bash
ready=$(herdr task list --status ready)
task_id=$(printf '%s\n' "$ready" | jq -r '.result.tasks[0].id // empty')

if [ -n "$task_id" ]; then
  herdr task dispatch "$task_id" implementer
fi

herdr task list --status blocked
herdr task list --status review
```

リポジトリと worktree の戦略上、並列編集が安全な場合は、独立した ready タスクを別々の名前付きエージェントで実行できます。ワークスペースとペインの作成、エージェントの起動、ライフサイクル状態の待機、ターミナル結果の読み取りについては、[エージェント自動化](/docs/agent-automation/)を参照してください。

## タスクの作成と確認

```bash
herdr task create --title "Add retry policy" --description "Document and test retries" \
  --cwd ~/src/project --agent-session-id "SESSION_ID"
herdr task board
herdr task list
herdr task get task-1
```

Herdr は各タスクに永続的で単調増加する ID（`task-1`、`task-2` など）を自動で割り当てます。タスク作成時に ID を指定する必要はなく、保存済みタスクリスト内の欠番は再利用されません。

コーディネーターが Codex、Claude、Pi、またはその他のエージェントのネイティブセッション ID をすでに把握している場合は、`--agent-session-id` で渡せます。Herdr はその値を永続化し、タスク API で返し、アクティビティ詳細に表示します。このフィールドは由来を記録するもので、セッションのアタッチや再開は行いません。

主なライフサイクル:

```text
backlog -> ready -> running -> review -> done
                       |  ^
                       v  |
                     blocked
```

依存関係があるタスクは、すべての依存先が `done` になるまで `backlog` に留まります。running の作業は `blocked`、`review`、`failed`、`cancelled` へ移行できます。failed タスクは、意図的な再試行のために `ready` へ戻せます。Herdr は `running` から `done` への移行を拒否し、review を明示的な受け入れゲートにします。

## ターミナル UI にタスクを表示する

ワークスペースのサイドバーからグローバルメニューを開き、`task panel` を選ぶと、タスクドックが `hidden`、`right`、`bottom` の順に切り替わります。ドックはターミナルの右側または下側に領域を確保するため、ワークスペースとエージェントのパネルをそのまま使えます。ドックをクリックするとフォーカスが移ります。`j`/`k` または Up/Down でタスクを移動し、`l`/Right または Enter でアクティビティを開き、`h`/Left、`q`、Escape でドックを非表示にせずターミナルへフォーカスを戻します。最初の行クリックでフォーカスして選択し、選択済みの行をもう一度クリックするとアクティビティを開きます。

同じメニューから `task board` を選ぶと、完全なステータス列ビューが開きます。`h`/`l` または Left/Right で空でないステータス列を移動し、可能な限り同じ行を維持します。`j`/`k` または Up/Down で現在の列内のタスクを移動します。選択したタスクで Enter を押すか、ボードの行をクリックすると、アクティビティモーダルが開きます。モーダルにはタスク ID、ステータス、割り当てメタデータ、新しい順のアクティビティが表示されます。アクティビティ時刻はローカルシステムのタイムゾーンで表示されます。`j`/`k`、Up/Down、Page Up/Page Down、またはマウスホイールでスクロールします。Escape はアクティビティを開いた画面、つまりボードまたはフォーカス済みドックへ戻ります。ボードで `p` を押すとドックを切り替えてボードを閉じます。

`herdr task board` は非対話のコマンドライン要約を出力します。対話型のボードとアクティビティモーダルには TUI メニューを使います。説明、依存関係、最後のメッセージ、構造化アクティビティを含む完全なタスクレコードが必要な場合は `herdr task get TASK_ID` を使います。

アクティビティ履歴には、作成、割り当て、配布、状態変更、エージェントの working/blocked/idle 遷移、解放イベント、明示的な進捗報告が含まれます。Herdr はタスクごとに最新 256 件を保持し、セッションと一緒に保存します。可視の進捗要約を記録し、エージェントの非公開の思考過程は記録しません。

狭い画面では右側のドックは自動的に下側へ移動します。ドックの配置はクライアント UI の状態であり、タスクデータとアクティビティ履歴はサーバーが所有します。

## エージェントの割り当てと配布

対象には、`herdr agent` が受け付ける実行中エージェント名またはワークスペース修飾付きペイン ID を指定します。これにより、Herdr 内ですでに実行中の Codex セッションを割り当てられます。

```bash
herdr task attach task-1 reviewer
herdr task dispatch task-1 reviewer
herdr task dispatch task-1 reviewer --prompt "Review the implementation and report review with evidence"
```

`task attach` はプロンプトを送らずにタスクとエージェントを関連付けます。`task dispatch` は対象を割り当て、タスクのタイトルと説明、または指定したカスタムプロンプトを次のプロンプトとして送信します。どちらのコマンドも Herdr 外のターミナルで起動したプロセスを取り込んだり、非表示のエージェントを作成したりしません。まず Herdr のペインでエージェントを起動してください。

実行中のペインを別のスペースへ移動するには、既存のペインレイアウトコマンドを使い、返されたペイン ID を保持します。

```bash
herdr pane move w1:p2 --new-tab --workspace w2 --focus
```

プロセスとタスクは実行を続け、ワークスペース修飾付きペイン ID だけが変わります。

## ライフサイクル進捗の報告

ワーカー、レビュアー、人間、コーディネーターは同じ報告インターフェースを使います。

```bash
herdr task report task-1 running --message "Added the retry path; writing tests"
herdr task report task-1 blocked --message "Need the retry limit from the API owner"
herdr task report task-1 running --message "Limit confirmed at three; tests are running"
herdr task report task-1 review --message "Implementation complete; just test passes"
herdr task report task-1 done --message "Review accepted"
```

すべての状態変更と空でないメッセージがアクティビティになります。`running` の繰り返し報告が許可されるため、エージェントは架空の状態遷移を作らずにマイルストーンを追加できます。明示的な報告により、タスク完了とターミナルのアイドル検出を分離します。アイドルのエージェントが追加指示を待っている場合もあるため、Herdr が作業を暗黙に完了扱いすることはありません。

## レビューと復旧

タスクが `blocked` の場合は最新アクティビティを確認し、示された問題を解決してから、作業再開前に `running` を報告します。タスクが `failed` の場合は失敗要約を保持し、入力、アプローチ、環境に具体的な変更がある場合だけ `ready` へ戻します。割り当てのたびに試行回数が増えます。

レビューでは、タスクレコード、差分または生成物、検証エビデンスを確認します。変更が必要な場合は `review` から `running` へ戻します。`done` は `review` からだけ報告できます。この明示的なゲートにより、依存タスクの解放とボード上の完了は、エージェントが入力を止めたことではなく、受け入れ済みであることを意味します。

## 自動化の境界

Herdr は、タスクの永続化、ID の割り当て、依存関係と有効な遷移の強制、実行中エージェントへの割り当てとプロンプト送信、アクティビティ記録、共有ボードの描画を自動化します。エージェントのライフサイクル状態も観察しますが、検出結果はオペレーターとコーディネーターのためのエビデンスであり、タスク成功の証明ではありません。

作業の分解、適切に分離されたワーカーの起動、ready タスクの選択と配布、承認対応、出力評価、再試行の許可、レビューの受け入れはコーディネーターが担当します。したがって、現在の Herdr では人間またはエージェントのコーディネーターを使って Symphony スタイルのワークフローを実行できます。完全に無人のキュースケジューラーは別の機能です。
