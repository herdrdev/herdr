---
title: 安装 Shepherd
description: 在 Linux、macOS 和 Windows 上安装、更新和验证 Shepherd。
---

Shepherd 为 Linux、macOS 和 Windows 提供稳定通道二进制文件。Windows 支持已正式发布,并记录了平台专用的已知限制和持续修复。

## 安装

在 Linux 或 macOS 上运行:

```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

在 Windows 上运行:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
```

如果端点安全软件阻止该无文件 PowerShell 命令，请打开命令提示符并运行：

```cmd
curl.exe -fsSLo install.cmd https://herdr.dev/install.cmd && install.cmd && del install.cmd
```

安装器会下载适合你平台的发布二进制文件并放到 PATH 上。新的直接安装默认使用稳定更新通道。现有的 Windows 预览安装会继续留在预览通道,直到你运行 `shepherd channel set stable`。在 Windows 上,PATH 指向当前带版本号的发布目录;安装器还会更新 `current` 和稳定的 `bin` 兼容别名,因此更新时不需要覆盖正在运行的 `shepherd.exe`。

## 用 Homebrew 安装

如果你已经在用 Homebrew:

```bash
brew install shepherd
```

## 用 mise 安装

如果你已经在用 mise:

```bash
mise use -g shepherd
```

如果 mise 报 `herdr not found in mise tool registry`,请更新 mise 后重试。旧版 mise 早于 Herdr 的注册表条目;`mise use -g github:herdrdev/herdr` 可以作为临时兜底。

## 用 Nix 安装

如果你已经在用 Nix,Shepherd 提供了一个从源码构建的 flake:

```bash
nix run github:herdrdev/herdr/v0.x.y
nix build github:herdrdev/herdr/v0.x.y
nix profile install github:herdrdev/herdr/v0.x.y
```

把 `v0.x.y` 替换为最新的发布标签。省略标签可以跟踪 `master`,但常规安装建议使用发布标签。

flake 还提供一个开发 shell:

```bash
nix develop github:herdrdev/herdr
```

更新时使用你安装 Shepherd 的同一套 Nix 工作流。对于 profile 安装,列出 profile 条目并升级 Shepherd 条目:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

如果 Shepherd 是你自己 flake 的一个 input,更新该 input 并重建你的系统、Home Manager 或开发环境:

```bash
nix flake update shepherd
```

## 手动下载

也可以从 [GitHub releases](https://github.com/herdrdev/herdr/releases) 下载二进制文件。

选择匹配你系统的产物:

| 系统 | 产物 |
| --- | --- |
| Linux x86_64 | `shepherd-linux-x86_64` |
| Linux aarch64 | `shepherd-linux-aarch64` |
| macOS Intel | `shepherd-macos-x86_64` |
| macOS Apple silicon | `shepherd-macos-aarch64` |
| Windows x86_64 | `shepherd-windows-x86_64.zip` |

在 Linux 或 macOS 上,赋予可执行权限并移动到 PATH 上的某个位置。

```bash
chmod +x shepherd-linux-x86_64
mv shepherd-linux-x86_64 ~/.local/bin/shepherd
```

### Windows 压缩包

稳定版发布和预览版预发布都会包含 `shepherd-windows-x86_64.zip`。压缩包包含 `shepherd.exe` 及其应用本地 ConPTY 运行时。请保留完整的解压目录,不要只复制 `shepherd.exe`。

## 验证

启动 Shepherd:

```bash
shepherd
```

如果 shell 找不到 `shepherd`,重启终端,或检查安装目录是否在 PATH 上。

## 更新

Shepherd 会检查新版本并在应用内通知你。也可以手动更新:

```bash
shepherd update
```

`shepherd update` 适用于由 Shepherd 自带安装器管理的安装。Homebrew、mise 和 Nix 安装请改用那些包管理器更新。

Linux、macOS 和 Windows 的直接安装默认使用稳定更新通道。要启用来自 `master` 的预览构建,设置通道:

```bash
shepherd channel set preview
```

用同样的方式把直接安装切回稳定版:

```bash
shepherd channel set stable
```

对于直接安装,切换通道时也会检查该通道并安装其最新二进制文件。如果该更新失败,运行 `shepherd update` 从配置的通道重试。

预览构建是从当前开发分支定期发布的 GitHub 预发布。当你想在下一个稳定版之前拿到修复时很有用,但它们可能出现回归。Homebrew、mise 和 Nix 安装不使用预览通道。

当稳定版的版本号高于最新预览构建的基础版本时,预览通道也会安装该稳定版。通道设置仍保留为预览,因此之后基于该稳定版发布的预览构建会自动成为更新候选。更新检查不会提供基于比已安装二进制文件更旧版本的发布。

Windows 的常规使用建议选择稳定版。预览版能更早获得修复,但可能出现回归,因此只有在接受这一取舍时才应主动启用。现有的 Windows 预览安装会继续留在预览通道,直到你明确切换。如果旧预览构建拒绝 `shepherd channel set stable`,请先在预览通道运行一次 `shepherd update`,再重试切换通道。

默认情况下,`shepherd update` 会安装新二进制文件,并让端点第 1 代服务器及其窗格进程继续运行。再次启动 Shepherd 即可用更新后的客户端重新连接。纯客户端改动会立即生效。新的服务器端操作会保持不可用,直到对应服务器更新并重启;客户端会显示通知,而不会断开连接。只有早于端点第 1 代的服务器需要在更新时再停止最后一次。

完成后,`shepherd update` 会列出仍在运行旧版本的服务器及重启它们的命令,以及运行各自 Shepherd 的已保存 SSH 机器。请在每台机器上也运行 `shepherd update` 来更新。

要对受支持的运行中会话启用实验性的实时服务器交接,运行:

```bash
shepherd update --handoff
```

当两个服务器都支持智能体状态传输时,实时交接会保留钩子上报的智能体状态,直到下一次上报到达。从较旧服务器交接时,运行中的智能体可能暂时显示为 idle。

实时交接不适用于 Homebrew、mise 或 Nix 的包管理器更新。这些安装先用包管理器更新,再重新运行 Shepherd,用更新后的客户端连接。兼容的旧服务器会继续运行。只有需要新版本的服务器端改动时,才稍后用 `shepherd server stop` 或 `shepherd session stop <name>` 重启它。

## 系统要求

Linux、macOS 和 Windows x86_64 都提供稳定通道二进制文件。受支持的工作流和已知限制见 [Windows 支持](/zh-cn/docs/windows-beta/)。Windows ARM64 通过 Windows 模拟运行 x86_64 构建。
